# 规划与执行面板

面板展示可审查的公开决策摘要：当前目标与约束、观察到的位置和背包、模型选择的下一步及简短说明、执行反馈、失败后的重规划、最终验证和用量。它不是模型内部隐藏推理的查看器，也不据模型文字认定成功。

## 使用

在仓库根目录运行，Windows 无需激活环境：

```powershell
.\.venv\Scripts\python.exe scripts/dev.py run --config config.json --dashboard
```

浏览器打开终端打印的 http://127.0.0.1:8765 。已在运行的旧 Agent 需要重启，才能写出逐步决策记录；无需重启 Minecraft 服务器。

内置面板随 Agent 关闭。如果希望保持面板、查看历史，另开终端独立启动：

```powershell
.\.venv\Scripts\python.exe scripts/dashboard.py --config config.json
```

默认只允许本机访问。如需让同一局域网的队友用浏览器查看，可显式使用 `--host 0.0.0.0`，让队友访问本机局域网 IP 的 8765 端口。面板只有只读接口，没有登录和指令执行接口；不要映射到公网。端口冲突时用 `--port 8766`，内置模式用 `--dashboard-port 8766`。

## 如何阅读

- “规划请求”：正在等待规划器根据当前观察提出下一步。
- “模型提案”：结构已经解析，目标含义和动作仍可能被后续校验拒绝。简短说明由模型公开提供，可能出错。
- “目标已锁定”：程序接受了可检查的目标谓词；尚不代表任务完成。
- “执行步骤 / 反馈”：实际查询或动作及返回证据。参数校验失败也会显示。
- “独立完成验证”：程序重新观察并核对目标；未通过会反馈下一轮，不能记作完成。
- “任务结束”：完成、失败、取消、等待澄清或预算耗尽。

这是一套单步反馈规划器，不会事先编造完整远期计划。时间线展示实际发生的步骤。模型省略公开说明时只显示它提出的操作，不补写解释。

可以筛选规划、动作和异常；点击任务切换历史，取消“跟随最新任务”后保留当前选择。“暂停刷新”仅暂停页面读取，游戏中的 Agent 仍继续运行。

## 日志与边界

新记录写入配置的 runtime_dir 下 trace.jsonl。原有 tasks.jsonl、requests.jsonl 和 usage.jsonl 继续保留。面板不读取密钥、配置内容或原始模型响应；旧版日志只展示结束摘要，不伪造其缺失的规划过程。

每个文件最多读取末尾2MB、最多展示600条事件和20个任务。日志正在写入时忽略不完整行；更早的完整证据仍保存在本机原始日志中。界面会提示历史窗口受限。

用量来自 API 返回记录，错误响应可能缺少用量，不能当作完整账户账单。页面读取成功仅表示面板进程可访问，不证明 Agent 仍在线；任务中断而未留下结束记录时，要结合终端判断。

离线演示仍标记为 scripted-demo；真实云模型与规则模式在规划调用卡片中区分。面板不改变权限、预算、停止、纠正或完成验证逻辑。
