# 采集与拾取可靠性修订

更新：2026-10-29。属于更新计划第二步的本地实现，不代表真实游戏验收完成。第一步零模型入口与其他Agent模式共用此执行底座。

## 本轮改动

- 原来挖完全部方块后集中拾取，改为确认每次挖掘后及时进行短轮拾取，最后再作完整收尾。所有拾取轮次共享30秒累计预算与64次接近尝试上限。单次第三方寻路若挂起，仍依赖动作取消机制，不能把预算结束视为底层已收敛。
- 从掉落实体的实际物品元数据识别目标，已知无关物品不作为拾取目标；未知元数据保留未知，不假称原木。明确的目标优先于尚未识别的实体。
- 根据掉落物当前位置选择有支撑、脚部和头部空间可读且无已知液体/火焰等危险的接近点；树叶支撑可用，但不猜测未知或被遮挡的空间。
- 掉落物明显移动或消失时，旧拾取路径的目标失效，返回观察并重新选位置。失败或到达后仍无目标增量的接近点，在目标位置未变时不立即重试；继续尝试其他接近点或其他目标。
- 原木达到所需增量后不再等待附近无关掉落。通用方块使用当前原版注册表的可能掉落物集合，不假定“方块名等于掉落物名”；其方块数量与具体产物数量仍由外部任务目标分别约束。
- 采集候选限制在动作起点32格内，稳定排序并降低不必要的向上追逐倾向；不可达、不能在该位置挖掘、目标变化等候选级失败会记录并排除。缺必需工具、装备未确认和挖掘效果不明确不盲目换目标继续。
- 背包满时检查是否有目标物品的可堆叠空间；装备调用返回后检查实际手持工具。
- 挖掘确认区分 confirmed_changed / unknown / timed_out。未知或未确认的挖掘不增加确认数量，标记 effect_unknown；Python 共用控制器停止自动变更，双层任务保留未知动作日志，动作调试要求核对并重新连接后再测。

没有搭桥、垫高或额外挖路；寻路仍禁止破坏和放置路面。无法找到可行路线时，应保留部分结果并失败，不扩展成自动地形改造。

## 可查看的信息

action_status 沿用原信封，effect 增加可选诊断信息，运行中也能读到当前快照：

- phase：precheck / search / navigate / equip / dig / pickup / verify / completed。
- mined_count、confirmed_mined_count、inventory_delta、gained_count。
- target_items、target_required_gain、pending_drops、unidentified_drops。
- pickup_target：实体ID、已识别物品、掉落位置、接近点和观察时间。
- pickup_attempts、drop_pickup_ms、pickup_diagnostics、failed_candidates（最后16条）。
- dig_confirmation、effect_unknown。

“附近实体数量”不等于“原木数量”，库存增量也不独立证明其来源于某一方块。测试应排除既有掉落和其他玩家投喂，结合确认挖掘数、实体与库存证据判断。

## 用户复测

关闭旧Bot，使用原来的 --action-debug 启动方式。无需密钥和模型调用。

1. 橡树基线：记录背包原木数量，输入 !agent collect oak_log 4。
2. 樱花树对照：记录樱花原木数量，输入 !agent collect cherry_log 4；覆盖地面、树冠和掉落到下方的情况。
3. 在附近放置无关掉落物，确认它们不会造成虚假完成或迫使满足目标后继续等待。
4. 验证最近目标不可达时会换目标；全部不可达时有界结束并提供原因。
5. 分别在移动、挖掘、拾取时输入 !agent 停止，核对没有新阶段继续启动，保留已有增量。

各场景恢复相同初始条件后再重复，记录代码提交、指令、初始/最终库存、确认挖掘数、耗时、失败阶段、是否人工介入和日志目录。不要把部分完成当成完成。

底层外部调用不返回时，当前策略是保持身体锁并保留未知状态，不保证无需重新连接即可恢复。场景中的高差不可达、无安全站位、背包已满等均可能合理失败；此次修改不承诺通用树木采集能力。

## 本地验证结果

- Python：149项通过；包含显式未知效果阻止后续动作、未知动作不被日志终态误洗成已确认。
- Node：48项通过；覆盖动态下落目标、树冠/地面接近点、部分增量、无关物品、不可达目标切换、候选排除、实际装备、区块未知确认和真正进入挂起调用后的停止锁。
- 既有Mock离线演示通过，没有连接真实服务器或调用模型。

测试是脚本替身证据。樱花树、橡树和停止的本轮实机复测尚未运行，由用户继续验证。
