# 开发路线

## M1 原版执行闭环

先在固定 Java 1.21.1 实验服逐项验收移动、采集、取放、合成和熔炼。冻结一个能复现的场景，验证“取料、合成、交付”端到端任务和停止。

退出条件：每项动作有前后观察，失败不会报完成，停止后不再启动旧动作。补充复合目标、容器增量基线与原料来源约束，使原方案示例完整验收成立。

## M2 中文理解与交互

抽出 TaskSpec，统一 intent、goal、bindings、constraints、completion、task_version。增加中文数量、增量/总量语义、对象指代、最少澄清和纠正测试集。

退出条件：对话中的“左边箱子”“不是这个”“保留四块木板”等有明确绑定与程序检查，中途纠正保留已完成进度，旧计划被版本拒绝。

## M3 经验与技能

先评测 B0/B1。再实现轨迹提炼候选技能、参数替换、前置条件检查、独立场景复验及 B2 自动执行。当前 SQLite 和晋升 API 为这一步提供底座。

退出条件：未见数量和位置任务能检验迁移，重复错误和调用开销有实际统计；同一场景重复成功不能充作独立复验。

## M4 受控规则变化与整合包

先建立服务器规则查询、物品注册表和能力协商通道，再加入少量新增物品或受控配方变化。B3 通过实际依赖指纹只使受影响技能失效。

退出条件：E0/E1/E2 环境中保持模型与工具预算可比，规则变化后验证旧技能误用和适应过程。复杂机器按类型逐项适配，不承诺通用模组 GUI。

## 小组分工建议

| 方向 | 主要目录 | 首个可审查交付 |
| --- | --- | --- |
| 中文交互与规划 | planning、domain | 目标解析集和 TaskSpec |
| 游戏执行 | executor、adapters | 原版动作的真实验收日志 |
| 状态与学习 | execution、memory | 取消、复验与经验检索闭环 |
| 评测与复现 | benchmarks、evaluation、scripts | 独立场景、重置和统计 |

按端到端任务协作，每次修改跨进程字段时同步 Python、Node、协议和测试。课程期限与成员尚未确认，因此不把开题中的六周建议当作实际承诺。
