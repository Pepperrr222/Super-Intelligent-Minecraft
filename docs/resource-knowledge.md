## 制作查询

```json
{"type":"crafting_options","goals":[{"item":"wooden_pickaxe","count":1}],"mode":"additional","includeDependencies":true,"expandMembers":false}
```

- `mode=total` 计算最终持有量缺口；`additional` 要求新增产物。多个目标统一预留库存，不重复占用。
- `groups` 将真实配方按原料显示类别与数量分组，例如木板组 × 3、木棍 × 2；不是凭名称推导游戏规则。`expandMembers=true` 返回成员列表；默认只返回已有成员与成员总数。组保留 `freelyMixable=false`，每个可执行选择仍对应真实完整配方，不能据分组臆造混搭。
- `alternatives` 返回按直接缺料量排序的前三个真实候选、数量、批次数、余量和短编号；有总数与截断标记。目标按顺序共享库存，选中候选缺料不证明不存在其他满足组合。
- `dependencies` 复用现有有界需求展开，支持共享库存、余量、设施复用。它是候选依赖，不是自动执行的技能；材料获取、导航、放置仍由 LLM 显式选择基本动作。
- `materialsReady` 仅检查当前背包的普通原料，不计历史容器库存；不证明设施存在/可达。依赖搜索仍只覆盖本地版本合成规则，无熔炼、返还容器、副产物或服务器自定义配方保证。
- 特殊属性原料从自动检查中排除，列入 `excludedSpecialItems`。名称级合成/容器转移不能保证避开同名特殊物品时拒绝，需先分开存放；没有擅自消耗特殊物品的默认策略。

`recipe:<16位内容摘要>` 是模型侧短引用。程序检测歧义、物品和版本绑定，转换为原生 64 位引用；旧 64 位引用兼容。V2 在模型复核前检查引用及可推算的同批材料消耗；前面有取放/采集等未知库存变化时不虚构其结果，实际执行时再次核对。工作台引用、整批材料、取消和单 Bot 租约检查保留。

## 缓存与模型上下文

每个 Bot 复用一个本地版本配方 Provider，最多缓存 128 个物品，来源/版本/修订变化清空。原生制作仍按当前规则解析引用，不直接执行旧缓存对象。

AgentState 持久保存最近 8 个成功制作查询规格（关联目标）；每次模型输入主动刷新当前目标最近 2 个查询的库存计算，复用本地配方缓存，不新增 LLM 请求。重启后根据保存的规格重新建立本地缓存，不将历史“材料足够”沿用为事实。完整历史查询保留在证据中，当前上下文不重复展开同一份结果。超大摘要明确提示缩小目标或关闭递归。

## 容器记忆

```json
{"type":"container_memory","items":["spruce_planks","stick"],"limit":8}
```

这是只读历史查询，不自动移动、开箱或取物。`container_inspect` 和 `container_transfer` 通过原有执行器开窗读取，在关闭前保存记录；成功取放刷新，转移异常标为 `invalidated`。迟到的取消窗口只关闭，不继续取材或记录为成功。

记录包含作用域、维度、位置、容器类型、观察时间、槽位名称/数量、特殊属性摘要。双箱依据方块朝向和左右类型确认两半，以同一库存标识去重；无法确认配对的 54 槽窗口不保存为两个独立库存。末影箱内容按同一 Bot 共享库存去重。方块名称/属性变化使相应记录失效。

记录最多 128 个，随 V2 AgentStore 写前日志和检查点持久保存；不是另一套并行文件写入器。所有关闭窗口后的记录均为 `historical`，始终 `requiresInspection=true`。跨重启、其他玩家操作和不可见区块变化不能保证新鲜，必须重新检查/取回并对账。只展示当前维度记录，不把容器记录当作使用权限或新鲜完成证据。

启动示例以服务器地址/端口/账号身份隔离存储；`MC_WORLD_ID` 进一步隔离世界。换档/重置同地址世界时设置新的 `MC_WORLD_ID`。协议通常没有可靠世界唯一标识，不能自动识别所有换档。嵌入使用时可显式设置 `knowledgeScope`，并使用持久 AgentStore。

制作查询自动附相关容器线索；上下文使用最多 8 个容器的物品汇总，每个最多 12 类并标记截断。完整槽位与必要属性仍保存在记忆中，可按物品查询。历史信息不授权取物；模型按既有玩家授权自主安排导航、检查和取材。

## 连续执行与验收

执行模型可以 `propose(continueStage=true, requestReview=false)` 在同一主控阶段继续；每阶段最多 12 次执行模型回合、6 次查询、4 个成功批次，仍受目标预算/期限限制。新方法（动作类型或非数量/引用参数变化）必须内部复核；相同方法可复用本阶段复核。失败、修订、取消或待对账立即结束连续执行。`stage_done` 只交回主控，不完成总目标；最终仍由独立 LLM 根据原话和新鲜证据自然语言验收。

这些措施降低重复查表和主控往返，但不保证具体 token 降幅。现有模拟回归证明同阶段续做可减少 director/review 调用；真实请求数、token 与成功率需新版实机记录比较。
