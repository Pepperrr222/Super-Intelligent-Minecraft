# 运行诊断界面

实现日期：2026-11-02。此界面读取真实 TypeScript 伙伴运行时的诊断记录，支持查看模型和程序各层决策；不会向 Minecraft 发出命令或操作。它不替代语义理解和持续目标规划的修复。

## 启动

1. 如果伙伴正在运行，先正常停止，然后重新使用 `启动AI伙伴.cmd` 或 `pnpm companion` 启动新版。旧进程无法自动安装新的采集钩子，历史截图也无法还原出不存在的模型日志。
2. 新版伙伴启动时显示 `http://127.0.0.1:4318`。诊断页在浏览器打开，即可在游戏中复现“到树旁”“过来捡木头”等指令。
3. 独立查看日志时双击项目根目录的 `启动诊断台.cmd`，它编译并打开浏览器；或执行 `pnpm diagnostics` 后访问上方地址。独立诊断台不登录游戏，会增量跟踪 `logs/diagnostics.jsonl`。

窗口保持打开，Ctrl+C 停止。端口可通过 `SIM_DIAGNOSTICS_PORT` 修改。若伙伴和独立诊断台同时使用 4318，后启动的伙伴会继续记录日志而不占用第二个端口；已有独立诊断台能跟踪这些记录。端口被其他程序占用时，改用不同端口。

## 如何定位问题

每条玩家消息有独立 traceId；异步任务绑定 taskId，控制器执行时恢复相应指令上下文，避免不同玩家/任务的事件混在一起。

| 环节 | 查看什么 | 可判断的问题 |
|---|---|---|
| 玩家输入 | 原话、玩家 | 输入是否完整、是否漏掉了复合要求 |
| 模型决策 | 脱敏上下文、原始返回、耗时 | 模型看到什么，是否选了 come_to_player/gather_wood 等错误技能 |
| 程序校验 | 解析后的决定、接受/拒绝、拒绝码 | JSON/参数/引用/权限/预算是否被拒绝；通过只代表结构与权限合法 |
| 交互分发 | 实际决定和程序阻断 | 查询完成后阻止后续任务、任务占用、旧决定、目标预算耗尽 |
| 任务调度 | 入队的完整任务和调度状态 | 模型建议与真正提交的步骤是否一致 |
| 步骤执行 | 步骤、技能、前后置结果、租约状态 | 哪一个步骤受阻、取消或失败 |
| 观测查询 | 查询参数、返回值 | 没有资源、未知状态、候选被截断等 |
| 底层动作 | 参数、结果、错误码、证据、耗时 | 是动作失败、API 完成、局部变化还是取消 |
| 验收反馈 | sourceText、taskGoal、RunFeedback | 程序是否把单次查询/移动的完成当成整条需求完成 |
| 玩家回复 | 发送给聊天网关的文本 | 程序准备回复什么；不证明对方实际收到 |
| 连接/运行时 | 启动、停止、连接错误 | 是否因模型或游戏连接问题尚未进入执行 |

重点先看“指令与执行对照”，再点击环节或时间线查看右侧 JSON。红色标记来自程序记录的错误/阻断；“仅显示程序报错或阻断”不会自动筛出所有语义理解错误。模型选择错技能却合法通过校验时，必须对照玩家原话与模型选择判断。

`CONTINUATION_DENIED` 会明确显示“后续任务被程序阻止”和被阻止的任务；它不再只是一句模糊的游戏聊天回复。本界面没有修复目标状态机，只让这类问题可追踪。

## 回放与边界

- 页面实时轮询，可暂停、按指令搜索、按环节/程序异常筛选、复制详情、导出当前窗口中的 JSON。
- 支持在浏览器本地导入诊断 JSON 或 JSONL；导入文件不会上传到外部服务器，也不会执行其中内容。最多显示最近 2000 条，文件限制 20MB。
- “查看演示”中的两条记录按用户截图构造，始终标明演示；不是真实模型结果，也不调用游戏。点击“返回实时”退出。
- 默认日志为 `logs/diagnostics.jsonl`，只在新版 companion 入口启用持久记录；直接构造 CompanionRuntime 默认使用内存，也可传入自定义 DiagnosticBus。
- 每个事件有深度、数组和字符串限制；超过大小会明确截断。内存最多 2000 条，文件达到约 20MB 后停止追加并提示归档。归档后重启伙伴可继续记录，不自动删除用户日志。
- API 密钥字段、授权信息、常见凭据文本、NBT/组件/指纹等在进入内存和文件之前脱敏。玩家聊天、游戏位置、参数和模型返回仍可能包含私人内容，分享导出文件前应自行核对。
- HTTP 只绑定 127.0.0.1，校验 Host/Origin，只提供 GET 页面和事件/导出接口，没有发聊天、执行动作、修改密钥或控制机器人的接口。
- 日志采集失败不抛入游戏执行流程；动作结果及现有取消/租约语义保持不变。诊断通过不等于语义或实机任务通过。

## 验证

新增 5 项自动测试覆盖脱敏与持久回放、并发指令/任务关联、异常/取消及内存限制、本机 HTTP 只读边界，以及模拟运行时里“过来捡木头→模型选择 come_to_player→执行→后续任务被程序拒绝”的完整诊断链。当前 256 项测试通过。

浏览器已验证空状态、明确标注的演示、模型选择对照、程序阻断筛选和 JSON 详情。未因本次界面工作连接真实游戏或调用付费模型。已有目标管理/意图偏移问题仍需单独改造。
