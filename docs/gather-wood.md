# 原木采集技能（实验版）

`gather_wood` 是首批动态技能中流程最完整的一个：内部组合 `find_blocks`、`inspect_block`、`navigate`、`dig` 和掉落物拾取，并在每一步前后重新观察。它通过调度器和控制器执行，不能直接控制 Bot。

## 输入与范围

- `woodType`：可选，`oak_log`、`spruce_log`、`birch_log`、`jungle_log`、`acacia_log`、`dark_oak_log`、`mangrove_log`、`cherry_log`之一。省略时自动选择附近候选最多的受支持树种；数量相同时取更近的。
- `count`：1–64，默认 1。
- `searchRadius`：1–16，默认 16。

只处理当前客户端已加载范围内、附近有对应树叶的原木。树叶邻近只用于确认候选是一棵树，不保证是一棵完整或允许采集的树；确认后会围绕该树干的水平范围继续采集，不再要求每一块原木都紧邻树叶。

## 执行流程

1. 记录背包基线。未指定 `woodType` 时，分别查询八种受支持原木及其树叶（原木和树叶分开查询，避免树冠占满最近方块列表），选择候选最多的一种，并在本次运行内固定该树种。
2. 原木和树叶使用独立的 `find_blocks` 查询。只查原木时最多返回最近的 128 块原木，树冠不会把它们挤出结果；选择一块上方 1–6 格、水平 3 格内存在对应树叶的原木确认树的位置。
3. 以该原木的水平范围记忆树的位置，后续优先采集同一树干区域内的原木，按距离排序；一棵树采集完后再选择下一棵。
4. 导航到目标所在水平位置的地面附近（而不是树干方块本身的高度），重新读取该方块。导航后置检查同时接受脚部取整节点和其上方一格，与 pathfinder 的完成判据一致，雪层或台阶上不会把已到达的导航误判为 `GOAL_NOT_REACHED`；接近位置的 y 会取整以符合动作参数的整数要求。
5. 目标仍是目标原木时挖掘一块。接近或挖掘失败（如 `GOAL_NOT_REACHED`、`OUT_OF_REACH`）时跳过当前这棵树，继续尝试同树种的其他树；不会因为一棵树不可达就结束整个技能。
6. 掉落物可能还在下落，先等待再按实体当前位置接近；单个掉落物最多尝试两次。
7. 查找并接近附近 `item` 实体，等待拾取，按背包中目标原木的增量确认。单次拾取未确认时记录并继续采集下一个目标；连续两次未确认才以 `PICKUP_UNCONFIRMED` 结束。
8. 未达到 `count` 时继续寻找下一个目标，最多尝试 `count * 3` 次，另加最多 6 次跳过不可达树的预算。

成功条件是背包中目标原木的实际增量达到 `count`。`dig` 动作完成、方块消失或掉落物出现都不算成功；没有观测到原木进入背包时返回 `partial`。显式指定的树种缺失时返回 `NO_ELIGIBLE_TREE`，不会自动换成其他树种；附近有树但都无法接近或挖掘时返回 `NO_REACHABLE_TARGET`，不会误报成“附近没有树”。

## 失败与停止

- `INVENTORY_UNKNOWN`：读不到背包，无法建立基线。
- `NO_ELIGIBLE_TREE`：附近没有带对应树叶的目标原木；已有部分收获时返回 `partial`。
- `NO_REACHABLE_TARGET`：附近有目标原木，但所有候选树都无法接近或挖掘；已有部分收获时返回 `partial`。
- `TARGET_CHANGED`：接近后目标方块被替换或消失。
- `PICKUP_UNCONFIRMED`：已挖掘但没有观测到目标原木进入背包。
- `ATTEMPT_LIMIT`：达到尝试上限仍未达到目标数量，`partial`。
- `CANCELLED` / `DEADLINE_EXCEEDED`：停止或超时；不再开始新的导航、挖掘或拾取。

取消不是回滚。已挖掉的方块不会恢复，已发出但未完成的动作可能仍产生效果；结果中的 `partialEffects` 记录已完成的动作和已观测到的采集数量。取消后上下文拒绝新查询，因此最终背包数量只能使用取消前最后一次观察。

## 已知限制

- 不识别玩家建筑、领地权限或服务器方块保护；技能也不会再弹二次确认，因此只应在你自己允许采集的测试区域使用。
- 不自动选择、切换或修复斧头，不检查工具耐久。
- 不会垫脚、攀爬或搭桥。树干高于交互距离（约 4–5 格）后，剩余原木可能无法挖掘；被挖掉下半截的树干可能悬空，只能尝试附近其他树。此时若所有候选树都不可达，技能返回 `NO_REACHABLE_TARGET`，不会假装采集成功。
- 每次查询最多查看 `searchRadius` 内最近的 128 块原木；超出这个范围或未加载区块中的原木不会被处理。
- 不检测背包满；背包满时通常表现为拾取未确认，掉落物可能留在世界。
- 掉落物实体不带物品身份，拾取阶段只能接近最近的掉落物并用背包增量验收，不能保证拾取的是刚挖出的原木。
- 不跨区块搜索，不保证砍完整棵树，也不处理树叶腐烂或树木悬空。
- 没有实机验证。当前只有模拟状态机测试，不能据此声称路径、掉落物拾取、树冠筛选或方块保护已在 1.21.1 服务器通过。

## 试玩方式

更新代码后先重启伙伴进程。配置意图模型后，在 Java 1.21.1 服务器聊天中尝试“砍树”“砍 3 个原木”或指定 `woodType`；通过程序校验后会直接开始，不再要求回复“确认”，“停”可中断。未指定树种时会自动选择附近可采集的树种。自然语言识别依赖模型，尚需实测。

建议先在可自由采集的测试区域从一个原木开始，记录服务器版本、位置、背包前后数量、实际掉落物和停止行为，再逐步增加数量与树种。技能级验证清单见 [skills.md](skills.md)。
