# 能力与验收边界

本文件区分代码能力、离线测试和真实游戏验收。报告只覆盖明确测试过的原版场景，不将规则基线或固定脚本写成通用 LLM 能力。

## 真实原版验收

2026-10-28 在官方 Minecraft Java 1.21.1、Java 21、本机隔离超平坦世界中运行完整验收。原始日志按运行编号保存在 runtime/acceptance/；公开摘要、官方服务端校验值及源码 SHA-256 见 [验收记录](../benchmarks/results/vanilla-2026-10-28.json)。

| 层次 | 检查内容 | 结果范围 |
| --- | --- | --- |
| 原子动作 | 观察、搜索、移动、停止、采集拾取、背包/工作台合成、箱子取放、熔炉取回产物、缺货失败、拒绝聊天命令 | 13项受控检查 |
| 任务验证 | 中文规则交付、旧库存不冒充新增、数量守恒、虚报拒绝、禁止移动 | 5项检查 |
| 真实玩家聊天 | 玩家指令、有限跟随、移动中纠正、跟随中停止、合成后改箱且不重复合成 | 5项检查 |

共23项检查，有共享场景和重叠证据，不能当作23个独立统计试验。

交付测试中来源箱实际减少2个原木，目标箱从已有5块木板增加至13块，角色材料与产物净变化符合复合目标。再次请求新增8块时，仅有旧库存不能通过完成判定。纠正在真正合成出8块木板后取消旧目标，将成品放入新箱，原目标箱保持不变。

摘要中的停止时间指“玩家发送停止至任务结束”，包含聊天和回执调度，不等于逐帧物理停步时间。原子动作另行检查停止后位置不再继续变化。

上述23项测试使用有限中文规则规划器、确定性动作脚本和对抗性虚报脚本。实际云模型单列在下方，没有宣称 B1/B2/B3 带来学习提升。

## 真实云模型验收

2026-10-28 接入 DeepSeek 官方 deepseek-flash 和 SiliconFlow deepseek-ai/DeepSeek-V3.2，两家均关闭思考模式，以 B0、每任务最多10轮、180秒上限在同一隔离原版夹具运行。四个场景为中文坐标移动、指定来源新增交付、保留材料并补料合成、无绑定指代澄清。规划全部来自实际 API，没有规则或固定动作回退。

移动检查真实坐标距离；交付独立检查来源原木减少2、目标木板新增8、角色原有3块木板保留且原木净变化0；合成检查木棍新增至少4、材料库存不低于3；澄清检查没有变更动作。完整通过情况、用量和对应源码校验值见 [云模型证据](../benchmarks/results/cloud-2026-10-28.json)。

开发记录包含失败，不能只将成功一轮理解为稳定成功率。发现的问题包括模型猜测歧义箱子坐标、输出扁平动作、把材料下限误作精确库存不变。程序在目标锁定前拒绝无绑定指代和无依据的保留材料精确增量，反馈模型重提；不会改写目标或替模型执行。澄清回复即使携带猜测目标，也不能触发容器基线检查。

每平台只有四个受控工程场景，各轮提示词和代码有变化，不是独立统计实验，也不能用于模型排名、学习提升或整合包兼容结论。

## 离线测试

Python 覆盖目标锁定、库存与容器基线、世界切换、复合条件、材料保留、禁止采集/移动、取消部分效果、纠正版本、澄清接续、经验作用域、技能晋升、HTTP模型契约及统计口径。

Node 覆盖生命周期、互斥、取消、部分效果、槽位读取、拾取判据、合成恢复、参数校验、并发和角色中心到达判据。

离线 demo 只验证 Mock 连通性。规则/脚本的规划步数与实际模型调用分开统计，不产生模型费用。CI覆盖 Windows/Linux × Python 3.12/3.13，以对应提交的运行结果为准。

## 真实测试发现并修复的问题

- 进度消息过密导致原版服刷屏踢出：限流并合并进度，重要消息受控发送。
- 寻路整数节点与角色真实距离不一致：统一世界坐标判据，不再额外放宽0.75格。
- 取消与回执竞争可能遗漏物品变化：停止后补采动作状态和背包，保留副作用与未知状态。
- 容器检查可能移动角色：全部检查后重新观察，再验证复合目标。

## 当前限制

- 仅原版普通动作，没有整合包兼容验收。
- 配方依赖版本注册表，尚无自定义服务端规则发现通道。
- 不支持任意GUI、复杂机器、代码生成、完整从零生存。
- 执行器面向本机 offline 实验服。
- no_move 保守地只允许不移动的只读查询，可能寻路的检查和动作被拒绝。
- 规则基线为有限语法，复杂指代和部分交付后的复杂纠正要求澄清。
- 候选技能存储与复验已实现，自动提取、参数绑定和技能执行待接入。
- 重启后自动恢复正在执行的任务尚未实现。
- 学习效果需要独立场景、冻结记忆和统一预算的正式实验。
