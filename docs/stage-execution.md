# 持续阶段执行

2026-11-03，sim-v2-7。新增通用结构化阶段解释器，应用于基本动作目录中的操作，不是挖石头专用技能。现有 45 动作/44 模型操作/14 查询不变，新增独立的 [阶段 Schema](stage-plan.schema.json)。

## 谁负责什么

当前 sim-v2-9 只有一个决策 LLM。明确重复阶段可返回 `kind:plan` 描述范围、方法、参数绑定、条件与循环；程序校验后解释器连续推进。正常节点之间没有 LLM 调用，没有额外模型复核。普通任务可直接 query/propose，不强制先写完整阶段图。

阶段完成、条件未知、前置失效、部分失败、限额耗尽或用户中断时，结果返回同一个决策模型。缺失数据报告失败路径与可用字段；上下文保留失败节点、已执行数量和是否需要对账。`stage_complete` 不代表玩家目标完成；模型返回 finish 后由程序核对证据引用和要求覆盖。

## 通用节点

| kind | 行为 |
|---|---|
| value | 保存模型明确提供的常量，例如已观察对象列表；它不是世界证据 |
| query | 执行现有只读查询，保存成功结果的 data |
| act | 绑定参数并解析现有 BasicOperation，通过原有 scheduler/controller/ActionExecutor 执行 |
| branch | 比较已产生结果中的标量，选择 yes/no；数组、对象、未知值不能当成有效判断 |
| foreach | 遍历明确列表，body 执行后跳回本节点；本节点输出当前项 |
| repeat | 最多重复指定次数，body 末尾跳回本节点；到上限走 next |
| end | 结束阶段，标记 stage_complete 或 needs_decision，交回主控 |

query/act 的参数放在 `query.params` / `operation.params`，`bindings` 无需绑定时写 `[]`。绑定示例：

```json
{"parameter":["targetRef"],"from":{"node":"each","path":["ref"]}}
```

含义：从 foreach 节点 `each` 当前项取得 ref，放到动作的 targetRef。没有任意 JS、表达式执行或隐含输入变量。节点类型和操作类型固定；实际参数绑定后必须再次通过原有 Schema。

静态检查要求 id 唯一、跳转存在、节点可达，且数据生产节点在消费者的所有路径上已执行；入口不能从尚无列表的 foreach 开始。字面量仅复用明确数据，不能制造有效 targetRef。运行时缺失字段、失效引用会交回主控，不自动换对象。

## 跨任务用法

- 搬运：检查来源箱 → 按授权数量取出 → 本地 verify 库存 → 分支 → 存入目的箱 → 观察结果。
- 制作：已有配方 → 顺序制作中间材料 → 装备/放置工作台 → 重新 observe_targets → 绑定新 tableRef → 制作产物。
- 采集：在模型给定范围 query → foreach 精确列表，或 repeat 内每次重新 query 并选择明确索引 → 逐块执行 → 本地 verify 阶段数量。挖掘不保证拾取，需按观察判断。
- 跟随/等待：复用有时限 follow、wait_until 原生动作；wait_until 通过事件检查，不需要 LLM 轮询。

引用有效期仍为 30 秒，不因方案已复核而放宽。长阶段应把重新观察放进循环，生成新引用；程序不擅自刷新引用并选其他目标。无法表达的选择规则交回模型。

## 约束、取消与持久记录

- 一份方案最多 48 节点、32KB、128 操作、300 秒、512 次节点转移，同时受当前目标额度和期限限制。单结果 16KB、输出池 64KB、输出与循环帧工作集 96KB；超限明确中断，不截断成假成功。
- 可选 guards 使用现有 Condition 定义。每次写前检查；运行时提供世界事件订阅时，健康、方块、拾取和库存变化也会触发 guards 检查。失效或未知时立即请求停止；在途原生操作仍持有租约，未结束前不能启动下一操作。
- 所有写操作只通过现有执行器。阶段不增加隐藏重试、技能回退或世界目标选择。失败不继续后续节点，部分效果保留待对账批次。
- 每个节点让出事件循环，取消、新消息和世界事件能够进入；分支自环也不能长期阻塞取消。
- goal.stage 持久记录方案、游标、循环计数/当前项、输出与 pendingNode。写前保存意图，成功后保存真实回执及下一位置。任务、聊天修订与阶段共享 epoch 校验。
- 重启把正在运行的阶段标记 interrupted，主控根据游标与回执重新观察、对账并提交剩余方案。**不会自动重放旧阶段或复用过期引用**。这提供恢复依据，不是无人参与的任意位置自动续跑。

## 验证记录

- 320 项自动测试通过，新增 13 项：覆盖十二操作连续执行、结果绑定、搬运条件循环、制作/等待、数据来源检查、预算、取消、实时 guard 中断、持久恢复不重放。集成测试中十二操作只调用一次 executor 和一次 review，仍由原有 Controller/Scheduler 执行。
- 使用真实 DeepSeek Chat 做两项合成场景检查：最终一次运行中，采集后制作只生成一次方案并连续执行 11 个模拟动作；搬运只生成一次方案并连续执行 6 个模拟动作。两者实际模拟库存均满足场景检查。
- 前两轮探针发现参数层级、未执行的数据源、数组直接比较数量等问题，补充格式示例、数据流校验和明确 value 节点后重测通过。不是把模型错误宽松解析成动作。
- 可复现命令：先 `pnpm build`，再 `node scripts/probe-stage-plan.mjs`。该脚本会使用已配置模型服务，每次最多 6 个请求，只发送合成场景与动作 Schema；不连接 Minecraft、不读取玩家日志。结果在忽略目录 `logs/stage-plan-probe.json`。
- 上述真实模型检查仍使用模拟世界，不代表真实服务器导航、掉落拾取、容器并发变化或长程任务稳定性已验收。
